# ADR 0004 P4 evidence-grounded verification

Status: approved P4 scope implemented for owner review. No architectural redesign or dependency additions.

The existing modular monolith and dependency direction remain. Domain owns strict candidate, decision, quote, attempt and claim-store models/ports. ClaimDrafter and VerifierAgent use the same RunModelPort and atomic BudgetedModel reservations as Planner. The infrastructure repository implements ClaimStore; neither agents nor HTTP handlers import SQLAlchemy or provider SDKs.

The owner explicitly requests uppercase SUPPORTED, CONTRADICTED and INSUFFICIENT_EVIDENCE. These map to locked supported, unsupported and insufficient. CONFLICTING remains a distinct additional outcome required by the frozen instructions; it requires two cited passages and stays outside the supported set. This is a vocabulary mapping, not a change to the rejection/research policy.

The graph extends the existing collection stage with draft, verify and verification_summary nodes and explicit conditional edges. Invalid plans skip research; invalid drafts skip verification; absent evidence skips drafting; exhausted budgets are recorded without extra requests. P4 has no edge back to Researcher and no synthesizer/final report. Historical P3 snapshots stay valid and the internal composition root's phase=P3 option reproduces historical collection-only fixtures; new API jobs always use P4.

Drafting uses bounded exact whole passages, a strict Pydantic output, validated task/ID membership, claim cap and lexical deduplication. Candidates are immutable unverified records. Model-generated atomicity is not deterministic proof of single-assertion quality. A distinct verifier prompt checks semantics, entities, dates, quantities, negation, context and conflicts. Matching a quote cannot establish entailment by itself. The application uses the Mesh result only after deterministic identity/citation gates.

The evidence loader checks source/run/task ownership, extraction success, canonical original URL, retained hash, full hash for untruncated text, stable passage ID, exact slice and saved candidate version. It runs before and after inference. Quote offsets are absolute extracted-text character positions. Final persistence rechecks the current text/hash/quote inside BEGIN IMMEDIATE, closing the final check/write window. Supported-set reads revalidate evidence; an integrity failure removes usability while preserving historical attempts. The full extraction hash of a truncated snapshot cannot be recomputed from its retained prefix; that limitation is explicit.

Alembic 0004 adds candidate_claims, claim_evidence and verification_attempts without altering earlier revisions. The original candidate JSON and text are preserved. Only real passages get FK associations; untrusted proposed IDs can remain on an unverified candidate and will fail verification. Attempt JSON stores strict verdict/quotes/offsets/hashes/rationale/model/usage/timing and rejection codes. Completed attempts cannot be overwritten. At most one pending attempt and two total internal attempts per claim bound repeated requests; the graph invokes one. Pending attempts become interrupted after a crash/restart. No retry HTTP endpoint exists.

A shared semaphore defaults to three verifications, with TaskGroup sibling cancellation/join on hard failure. Reservations remain transactional across all roles and concurrent tasks. A model limit, char limits, output limits, HTTP timeout and workflow deadline bound work. Pricing is not known, so monetary estimates are not inferred from tokens or fixture credits. Provider usage stays unknown if absent; token estimates explicitly use a character heuristic and are not tokenizer measurements.

Source text is JSON user data under a fixed system prompt, never a tool/system message. Verifier has no retrieval or executable tools; only validated persisted IDs/quotes may be accepted. Raw model payloads and exception bodies are not logged. Tracing remains disabled. Prompt-only semantic isolation is not a guarantee against an adversarial model or successful injection; independently reviewed live evaluation remains outstanding.

The P4 evaluation slice prepares a typed interface, reviewed-template loader and deterministic metrics. It creates no reviewed labels, corpus or benchmark results. Synthetic mocked semantics validate workflow/gates, not live reasoning accuracy. Corrective research, report synthesis and full evaluation remain future approved phases.
