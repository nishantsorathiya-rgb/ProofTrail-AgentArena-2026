# ADR 0005 bounded correction and grounded reports

Status: P5 implemented for owner review. Architecture and dependencies remain unchanged.

The owner explicitly approves **a maximum of two research retries per unresolved area**. This supersedes the older one-retry ceiling in AGENTS.md and CODEX_START_HERE.md for this phase. The frozen guidance files remain unchanged; configuration now defaults to two and rejects values above two. An area is an original Planner subquestion, with immutable child retry assignments. Overall task, search/fetch, model and time budgets still apply.

The P4 graph extends through explicit verification_decision, plan_retry, retry_research and reverify nodes. Reverification returns to verification_summary and the actual conditional decision. A retry invokes the existing Researcher and P2 collector; it cannot succeed by merely recording an event. Missing evidence, incomplete drafting coverage and completed semantic insufficiency can justify research. Contradicted/conflicting claims and operational/invalid-citation failures cannot trigger confirmation research. FollowupPlanner uses the same Mesh budget boundary to propose focused searches for eligible gap IDs. Unknown gaps, duplicate queries, oversized/invalid plans and no-useful-followup responses stop correction safely.

The initial default remains three research tasks and three-way bounded concurrency. MAX_RESEARCH_TASKS_PER_RUN defaults to nine, including retries; MAX_RETRIES_PER_SUBQUESTION defaults to two. Per-root persistent counts, a SQL uniqueness/number check, immutable retry assignments, lexical query deduplication, global atomic reservations, the workflow deadline and a task-derived LangGraph recursion ceiling bound the loop. Reserving a request never increases a persisted provider budget. No pricing-based dollar limit is inferred without known prices/account data.

Original candidates are immutable. New evidence is associated separately with eligible claims and every attempt freezes its exact cumulative evidence scope. The original source evidence remains in subsequent verification input. Supported claims in the same area are also rechecked when new evidence could change their support; contradicted/conflicting outcomes are preserved rather than searched for agreement. New claims are drafted only when an area has none to reverify, with global count and cross-batch deduplication. Every verdict change requires a new actual Mesh verification call. Retrieving more sources alone never grants support.

Novelty is based on exact passage-text hashes within an area. Cached copies, repeated URLs and identical text under a different source version are persisted as retrieval outcomes but do not trigger fake reverification. This detects exact copies, not semantic near-duplicates. Changed/new passages can still be irrelevant: the semantic Verifier must decide. Cumulative scopes exceeding eight passages or the configured text bound fail safely; earlier contradictory context is never silently dropped to fit.

SynthesizerAgent is a distinct invoked Mesh role. It receives only supported claim records, selects executive-summary IDs and organizes all findings using a closed heading vocabulary. Arbitrary model-written factual prose, URLs, quotations, invented IDs and additional fields are rejected. The application inserts exact original verified claim text and constructs citations from persisted verification quotes and source metadata. This limits stylistic freedom in exchange for deterministic factual containment. Limitations, unresolved gaps, rejected candidates, disagreements, methodology and operational errors are rendered from application state in clearly separate sections.

Synthesis failure or budget exhaustion yields an explicitly deterministic **incomplete** document containing only already verified text, not a fake successful model report. Empty evidence produces an empty/incomplete result. Run completion and research completion are distinct: a finished execution can have partial, insufficient, budget-exhausted or failed research. The report schema and API retain these distinctions.

The graph passes a strict report serialized as pending_report_json between synthesis and validation; it is persisted for interruption detection and excluded from HTTP status responses. The final report transaction checks original question, run, claim text, current supported status, latest successful semantic attempt, exact quotes/offsets, source/evidence IDs, source URL/title and hashes. Stored reports are immutable, checksummed and revalidated on read. A changed source or citation makes the report unavailable rather than serving stale verified findings. JSON and escaped plain-text Markdown represent the same validated report.

Alembic 0005 adds research_retries and final_reports and extends subquestions with parent/round metadata and verification_attempts with frozen evidence scopes/retry IDs. Existing candidate JSON, decisions and earlier migration files are preserved. Retry rows project typed workflow history; immutable intent fields cannot be rewritten. Actual prior/new verdicts, source IDs, timings, fixed error codes and ordered events remain inspectable. Coordinator shutdown/restart interrupts pending research/verification, clears unvalidated report drafts and does not replay jobs.

New endpoints add audit, retries and report retrieval to existing 202 admission, status, evidence and claims. Pending report retrieval returns 202, unknown runs 404, invalid/unavailable reports 409 and malformed format requests 422. These are local single-process endpoints, without authentication, cloud queues or production deployment. Existing P3/P4 composition modes remain available to reproduce historical phase fixtures; default API work is P5.

All model work still uses the sole MeshLLMAdapter. Tavily remains retrieval only, with existing URL/SSRF checks, retries, cache and usage reservations. Source/model text cannot alter retry policy, budgets or tool permissions. No direct fetcher or model fallback was introduced. Offline fixtures exercise actual nodes, SDK serialization, adapters, SQL and validation but do not measure live semantic quality, injection resistance, billing or research performance. P6 evaluation and all release work require separate approval.
