# ADR 0002 Tavily retrieval and exact evidence

Status: P2 implementation for owner review. The approved architecture remains the modular monolith described in ADR 0001.

SearchPort and ExtractPort belong to the domain alongside typed discovery, extraction, source, passage, outcome and usage records. EvidenceCollector depends on those ports, a URL-policy port and persistence ports. Infrastructure provides Tavily Search/Extract, shared async HTTP, public-source URL validation and SQLite repositories. A separate composition root makes the internal collection service runnable without creating P3 agents or P5 research endpoints. No new dependency is required; HTTPX was already pinned in P1.

One reused Tavily HTTP client targets only fixed search/extract endpoints. Basic search disables answer generation and auto parameter selection. Extract returns untrusted plain text; failures are checked per URL even on HTTP 200. Missing, contradictory duplicate or unsolicited result URLs are never accepted as evidence. Search snippets remain discovery data only. Provider errors are stored/logged as fixed codes without bodies, keys, queries or page content.

The same semaphore bounds search and extract I/O. SQLite atomically reserves every actual search request or extracted-URL attempt before sending it, including transport retries, and stores pending/final usage records. Initial run caps persist across clients and cannot be expanded just by resetting a client. Transient retries have bounded exponential backoff; 429 shares a cooldown across the client, Retry-After is respected, and excessive provider delays stop rather than trigger premature retries. Dollar billing remains unknown unless independently inspected; returned credits are optional metadata.

Source snapshots are immutable versions scoped to a run, URL, full/retained text hashes and UTC extraction timestamp. Stable passage IDs use source ID plus exact offsets/text. Bounded retention preserves a prefix without normalization; full extraction text hash and original character count distinguish truncated snapshots. Locators refer to the exact Tavily extraction text. No extracted statement is semantically verified in P2.

Successful extracts populate a persistent TTL cache. Reads do not extend freshness. Cache checks source URL, extraction time and content integrity; invalid entries are refetched. A hit for another run produces a run-scoped snapshot and passage IDs while retaining original freshness. Failed extractions are not cached. Weakly held URL locks avoid duplicate concurrent extraction within one runtime. Multiple independent runtimes/processes can still fetch the same uncached URL; this project remains single-process and does not claim a distributed cache lock. Historical snapshots are retained; garbage collection is deferred.

The URL policy rejects unsupported schemes, credentials, unusual ports, malformed encodings, nonpublic address literals, private/reserved names and any nonpublic DNS answer. URLs are revalidated before extraction and acceptance, including cache use. Original URL and canonical identity are stored separately, and query semantics are preserved. No arbitrary source request is issued by ProofTrail. Tavily's actual fetching, redirects and DNS resolution remain under Tavily control; local DNS validation cannot bind Tavily's request to a checked IP. Direct fetching would require a separately reviewed SSRF-safe implementation.

Alembic 0002 adds sources, passages, search/extract outcomes, cache, usage and budget tables without modifying 0001 or deleting P1 runs. Database foreign keys and ownership/exact-passage checks protect storage integrity. No optional live command runs automatically. The owner-only smoke command requires both live approval and acknowledged free-credit verification, is capped to two provider requests and one selected URL, and disables retries. Its flags do not prove billing status. P3 requires explicit owner approval after this phase's real tests and review.

Provider contracts were checked against the official [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) and [Tavily Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract) references. Test provider credits and content are explicitly synthetic fixtures.
